# 测试方案

## 1. 测试原则

规则计算必须由单元测试覆盖；闹钟与 Receiver 必须由真机/模拟器验证；后台启动效果必须在真实目标 ROM 上观察日志和通知，不以单元测试替代。

## 2. 单元测试

| 编号 | 输入 | 预期 |
|---|---|---|
| UT-01 | 周三 17:59，`WEEKDAY 18:00` | 当天 18:00。 |
| UT-02 | 周三 18:00，`WEEKDAY 18:00` | 下一工作日 18:00。 |
| UT-03 | 周五 18:01，`WEEKDAY 18:00` | 下周一 18:00（无调休）。 |
| UT-04 | 2026-04-30，`MONTHLY day=31` | 跳过 4 月，取 5 月 31 日。 |
| UT-05 | 2027-03-01，`YEARLY 2/29` | 2028-02-29。 |
| UT-06 | 节假日缓存标记某周六为 `WORKDAY` | `WEEKDAY` 任务匹配。 |
| UT-07 | 缓存过期且网络不可用 | 回退普通星期规则并返回警告。 |
| UT-08 | 结束日期早于候选日 | 返回 `NoNextTrigger`。 |

## 3. 数据库测试

- 插入任务后 `enabled=true` 与 `next_trigger_at` 可被索引查询。
- 删除任务后关联日志的 `task_id` 置空或根据外键策略可查，日志保留到清理任务。
- 每次 `Migration`：从上一版本建库、执行迁移、读写新字段并验证无数据丢失。
- 并发启停同一任务：最终只保留一个确定状态和一个下次时间。

## 4. 集成测试清单

| 编号 | 步骤 | 预期 |
|---|---|---|
| IT-01 | 创建 2 分钟后单次任务，授予精确闹钟 | Receiver 收到广播、日志依序出现、任务完成。 |
| IT-02 | 创建每天任务后关闭开关 | 旧 PendingIntent 被取消，日志有 `ALARM_CANCELLED`。 |
| IT-03 | 创建任务后重启手机 | 启动完成后任务重新登记，首页显示合理下次时间。 |
| IT-04 | 修改系统时区 | Receiver 重算，不沿用旧时区的 `nextTriggerAt`。 |
| IT-05 | 撤销精确闹钟权限 | 任务转为待授权，UI 有引导，不能伪显示已调度。 |
| IT-06 | 卸载目标 App 后触发 | 写 `TARGET_UNAVAILABLE`，发通知或在首页提示。 |
| IT-07 | 拒绝通知权限后触发 | 启动请求仍被记录，保底通知失败原因可见。 |

## 5. 真机与系统测试

| 环境 | 必测项 |
|---|---|
| Android 8 | 基本单次/周期任务、重启恢复。 |
| Android 12 | 精确闹钟特殊访问、Doze。 |
| Android 13 | 通知运行时权限、受限应用状态。 |
| Android 14 | 后台 Activity 与 PendingIntent 限制。 |
| Android 16 | `targetSdk 36` 行为、后台启动严格模式（如可用）。 |
| 自用 ROM | 息屏、低电量、省电模式、应用被划掉、重启。 |

### Doze 验证（开发机）

```bash
adb shell dumpsys deviceidle force-idle
adb shell dumpsys alarm | grep com.example.timestart
adb shell dumpsys deviceidle unforce
```

期待结果：具备精确权限的 `setExactAndAllowWhileIdle` 任务能在预期时间附近投递；日志记录触发时间。测试结束后必须退出强制 Doze。

## 6. 验收检查表

- [ ] 新建“工作日 18:00 → 企业微信”并正确显示下一次。
- [ ] 精确闹钟未授权时，明确显示待授权而不是伪调度。
- [ ] 重启/时区变化后执行重算。
- [ ] 目标应用不可用时不崩溃且有日志。
- [ ] 后台启动无法确认时，文案不显示“启动成功”。
- [ ] 日志不含敏感数据，30 天清理有效。
- [ ] 无网络时基础星期规则可用。

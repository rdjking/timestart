# 本地日志与数据埋点需求

## 1. 原则

不接入友盟、Firebase Analytics、神策等云端埋点。本项目以 `execution_logs` 作为**本地诊断日志**，用于回答“任务是否登记、是否触发、为什么没有打开”。

## 2. 事件字典

| 事件 | 触发点 | 必填结果码 |
|---|---|---|
| `TASK_CREATED` | 保存新任务 | `OK` |
| `TASK_UPDATED` | 编辑任务 | `OK` |
| `TASK_ENABLED` / `TASK_PAUSED` | 开关切换 | `OK` |
| `ALARM_SCHEDULED` | 成功登记下一次闹钟 | `EXACT` / `INEXACT` |
| `ALARM_CANCELLED` | 取消闹钟 | `OK` |
| `ALARM_TRIGGERED` | Receiver 收到闹钟 | `OK` |
| `RULE_SKIPPED` | 当前日期不匹配 | `SKIPPED_BY_RULE` |
| `LAUNCH_REQUESTED` | 已调用启动请求 | `REQUEST_SENT` |
| `LAUNCH_EXCEPTION` | 启动调用抛异常 | `ACTIVITY_NOT_FOUND` / `SECURITY_EXCEPTION` / `UNKNOWN` |
| `NOTIFICATION_POSTED` | 发出保底通知 | `OK` / `NOTIFICATION_DENIED` |
| `RESCHEDULED` | 重启、时区变化、前台恢复 | 原因枚举 |
| `HOLIDAY_FALLBACK` | 节假日资料不可用 | `CACHE_MISS` / `NETWORK_ERROR` |

## 3. 单条记录示例

```json
{
  "taskId": 12,
  "occurredAt": "2026-07-15T10:00:00Z",
  "eventType": "LAUNCH_REQUESTED",
  "resultCode": "REQUEST_SENT",
  "message": "已向系统请求启动 com.tencent.wework；系统可能限制后台显示。",
  "metadata": {"sdkInt": 36, "executionMode": "TRY_LAUNCH_THEN_NOTIFY"}
}
```

## 4. 日志 UI 与保留

- 首页可从任务溢出菜单进入“查看日志”。
- 日志详情显示本地化时间、事件、结果和说明；支持复制，不提供上传。
- 应用启动时，如距上次清理超过 24 小时，则删除 30 天前的日志。
- 不记录通知正文、目标应用内部页面、用户账号、应用使用时长、设备 ID 或 IP。

## 5. 诊断决策表

| 最近日志组合 | 页面诊断文案 |
|---|---|
| 无 `ALARM_TRIGGERED` 且已启用 | “闹钟可能未被系统投递。请检查精确闹钟权限、电池限制，并重新打开本应用。” |
| 有 `ALARM_TRIGGERED`、有 `LAUNCH_REQUESTED` | “已发送启动请求；Android 可能阻止后台将目标应用显示到前台。” |
| `TARGET_UNAVAILABLE` | “目标应用已卸载、被停用或无启动入口。” |
| `NOTIFICATION_DENIED` | “通知未授权，无法提供点按打开的保底提醒。” |

# 发布与自用部署指南

## 1. 构建签名

1. 使用 Android Studio 生成一个本地 keystore，妥善离线备份；不要提交到 Git。
2. 为 release 构建配置签名，输出 `app-release.apk`。
3. 保持相同 `applicationId` 和签名；否则更新安装会被视为不同应用。
4. 在真机卸载旧调试包前导出任务（如未来实现导出）；当前 MVP 应先确认无重要任务。

## 2. 安装

```bash
adb install -r app-release.apk
adb shell am start -n com.example.timestart/.MainActivity
```

首次打开后完成精确闹钟授权、通知授权（推荐）、创建一个 2 分钟后的测试任务，再创建正式任务。

## 3. 自用设备设置

1. 在应用“设置与可靠性”中确认“闹钟和提醒”已授权。
2. 建议允许通知，否则后台启动被系统限制时没有用户点按打开的保底入口。
3. 如目标 ROM 经常延迟/漏发，手动在系统电池设置中选择“不受限制”或等价选项；名称因厂商而异。
4. 不要强制停止本应用；强制停止会取消其后续后台执行能力，需重新打开应用。
5. 手机重启后打开一次首页，确认每个任务显示下次执行时间。

## 4. 交付前自检

- [ ] release APK 能安装在实际自用手机。
- [ ] 首次启动无崩溃，权限页状态正确。
- [ ] 2 分钟单次任务可从息屏状态触发并写日志。
- [ ] 目标应用不可启动时通知与日志表现正确。
- [ ] 应用重启后任务仍显示且重新登记。
- [ ] 可解释 Android 可能限制后台 Activity 启动，用户不会误解为硬保证。

## 5. 常见故障排查

| 现象 | 先检查 | 处理 |
|---|---|---|
| 到点没有任何日志 | 精确闹钟授权、应用是否被强制停止、电池限制 | 重新打开应用并查看权限页，创建短期测试任务。 |
| 有触发日志但目标 App 未显示 | `LAUNCH_REQUESTED`、系统版本、屏幕状态 | 这是后台启动限制的典型表现；使用通知“打开”动作。 |
| 重启后无下次时间 | 是否收到重启广播、是否处于受限状态 | 打开首页触发全量重算，并检查系统限制。 |
| 看不到目标 App | 包可见性、是否有 Launcher Activity | 用应用选择页搜索；手动包名验证。 |
| 工作日不符合调休 | 节假日缓存时间与来源 | 刷新缓存，或关闭“中国调休”后使用普通星期规则。 |

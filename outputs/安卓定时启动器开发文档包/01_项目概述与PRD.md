# 项目概述与产品需求文档（PRD）

## 1. 基本信息

| 项目项 | 定义 |
|---|---|
| 产品名 | 定时启动器（内部包名建议：`com.example.timestart`） |
| 目标用户 | 开发者本人 |
| 运行模式 | 本地离线优先，无账号、无广告、无自建后端 |
| 核心例子 | 工作日 18:00 尝试启动企业微信 |
| 首发平台 | Android 8.0（API 26）及以上 |

## 2. 问题与目标

用户希望在固定时间打开指定应用，避免遗漏下班处理消息、早晨打卡或周期性事务。第一版解决“按规则调度 + 尝试拉起应用 + 显示可追溯结果”这一闭环。

### 成功标准

- 用户能在 60 秒内创建“工作日 18:00 → 企业微信”任务。
- 任务保存后可看到下次执行时间和权限状态。
- 手机重启、时区/系统时间变化后，应用在下次启动或收到可用系统广播时恢复任务。
- 任何失败都有一条本地日志，包含失败阶段与可操作建议。

## 3. MVP 范围

### 必须支持

- 从可见应用中选择目标应用；也可粘贴包名进行精确选择。
- 单次、每天、周一至周五、周六日、自定义星期、每月固定日、每年固定月日。
- 任务的新建、编辑、复制、启停、删除。
- 精确闹钟授权引导、通知授权引导、开机恢复、时间变更恢复。
- 触发后尝试启动、重新计算下一次、写入本地执行日志。
- 通知点击作为后台启动受限时的保底打开路径。

### 不在 MVP 中

- AccessibilityService 自动点击、自动打卡、消息发送。
- 云同步、远程控制、多设备协同、分享任务。
- 自建节假日服务、保证任何 ROM 的后台保活。
- 对第三方应用成功打开后的页面状态做验证。

## 4. 用户故事与验收

| 编号 | 用户故事 | 验收条件 |
|---|---|---|
| US-01 | 我想选择已安装应用作为目标 | 显示应用名、图标、包名；不能启动的应用给出说明。 |
| US-02 | 我想设置工作日 18:00 | 保存后卡片显示“周一至周五 · 18:00”和下一次时间。 |
| US-03 | 我想暂停任务 | 开关关闭后取消对应 PendingIntent，卡片显示“已暂停”。 |
| US-04 | 我想在重启后继续生效 | 开机恢复时从数据库重算并注册所有启用任务。 |
| US-05 | 我想知道为何失败 | 日志能区分权限不足、包不存在、规则跳过、启动请求异常和系统限制风险。 |
| US-06 | 我想避免法定节假日启动 | 开启“中国调休”可选项后，优先使用已缓存节假日资料；无资料时明确降级为星期规则。 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 隐私 | 不上传任务、已安装应用列表或日志。 |
| 可靠性 | 单个任务的失败不得阻断其他任务重算。 |
| 性能 | 首页读取本地任务列表 P95 小于 300 ms（中端真机，100 条任务内）。 |
| 电量 | 不常驻前台服务作为默认方案；每个周期任务仅登记下一次闹钟。 |
| 可解释性 | 界面不以“保证启动”表述，展示“尝试启动/系统可能限制”。 |

## 6. 风险与产品决策

| 风险 | 决策 |
|---|---|
| 后台拉起被系统拦截 | 采用“尝试启动 + 通知点击保底 + 日志”而不是承诺全自动。 |
| 精确闹钟权限被拒 | 保存规则但将任务标为“待授权”；可选降级为不精确提醒。 |
| 目标 App 卸载/禁用 | 执行前检查可启动 Intent；记录并在首页标记“目标不可用”。 |
| 调休资料不准 | 接口资料缓存带来源和过期时间；失败时回退普通星期判定。 |

## 7. 发布判定

MVP 仅当“单次/每天/工作日规则、启停、删除、精确闹钟引导、重启恢复、日志查看、通知保底”均通过 [12_测试方案.md](12_测试方案.md) 的真机测试后，才允许安装为日常自用版本。

# 用户流程、业务流程与状态机

## 1. 创建任务流程

```mermaid
flowchart TD
  A[首页点击新建任务] --> B[选择可启动应用]
  B --> C[设置时间与规则]
  C --> D{表单合法?}
  D -- 否 --> C
  D -- 是 --> E[保存至 Room]
  E --> F[计算下一次触发]
  F --> G{具备精确闹钟权限?}
  G -- 是 --> H[注册精确 Alarm]
  G -- 否 --> I[标记待授权并显示引导]
  H --> J[返回首页显示下次时间]
  I --> J
```

## 2. 闹钟执行流程

```mermaid
flowchart TD
  A[系统发送 PendingIntent 广播] --> B[AlarmReceiver]
  B --> C{任务存在且已启用?}
  C -- 否 --> Z[记录忽略原因并结束]
  C -- 是 --> D{日期规则仍匹配?}
  D -- 否 --> E[重算并注册下一次]
  D -- 是 --> F[先重算并注册下一次]
  F --> G{目标应用有启动入口?}
  G -- 否 --> H[写 TARGET_UNAVAILABLE 日志并通知]
  G -- 是 --> I[尝试 startActivity]
  I --> J[写 LAUNCH_REQUESTED 日志]
  J --> K[按策略或异常情况发布通知保底]
```

## 3. 重启与时间变化恢复

```mermaid
flowchart LR
  A[ACTION_BOOT_COMPLETED / MY_PACKAGE_REPLACED / TIME_SET / TIMEZONE_CHANGED] --> B[RescheduleReceiver]
  B --> C[读取全部启用任务]
  C --> D[按当前本地时区重算]
  D --> E[取消旧 PendingIntent]
  E --> F[注册每个任务的下一次闹钟]
  F --> G[写 RECALCULATED 日志]
```

`BOOT_COMPLETED` 不是绝对可靠：处于受限状态的 Android 13+ 应用可延迟收到该广播。因此首页启动时也必须执行一次全量重算。

## 4. 单任务状态机

```mermaid
stateDiagram-v2
  [*] --> DRAFT
  DRAFT --> SCHEDULED: 保存且已授权
  DRAFT --> AWAITING_PERMISSION: 保存但无精确闹钟授权
  AWAITING_PERMISSION --> SCHEDULED: 授权后重算
  SCHEDULED --> TRIGGERING: 闹钟到达
  TRIGGERING --> SCHEDULED: 周期规则，已注册下次
  TRIGGERING --> COMPLETED: 单次任务，已写执行日志
  SCHEDULED --> PAUSED: 用户关闭
  AWAITING_PERMISSION --> PAUSED: 用户关闭
  PAUSED --> SCHEDULED: 重新开启且已授权
  PAUSED --> AWAITING_PERMISSION: 重新开启但无授权
  SCHEDULED --> EXHAUSTED: 无合法下一次日期
  COMPLETED --> SCHEDULED: 用户编辑为新规则
  EXHAUSTED --> SCHEDULED: 用户修正规则
  DRAFT --> DELETED: 用户取消
  PAUSED --> DELETED: 用户删除
  COMPLETED --> DELETED: 用户删除
  EXHAUSTED --> DELETED: 用户删除
```

## 5. 执行结果状态

| 结果 | 含义 |
|---|---|
| `LAUNCH_REQUESTED` | 已调用系统启动请求；不能证明目标界面可见。 |
| `NOTIFICATION_POSTED` | 已发送用户点击可打开的保底通知。 |
| `SKIPPED_BY_RULE` | 触发时规则不再匹配，例如调休资料更新。 |
| `TARGET_UNAVAILABLE` | 包被卸载、禁用或没有启动 Activity。 |
| `EXACT_ALARM_DENIED` | 没有精确闹钟授权，未登记精确闹钟。 |
| `SCHEDULING_ERROR` | AlarmManager 或 PendingIntent 操作异常。 |
